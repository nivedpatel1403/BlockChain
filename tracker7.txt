EXPERIMENT 7: SOLIDITY SMART CONTRACT - BALANCE TRANSFER (BalanceTransfer.sol)
AIM: Compile, deploy (with funding), and test transfer function of a contract
that only the owner can use to send contract's Ether balance out.
REQUIREMENTS: Remix IDE.
CODE (BalanceTransfer.sol):
```
// SPDX-License-Identifier: GPL-3.0
pragma solidity ^0.8.0;

contract BalanceTransfer {
    address public owner;

    constructor() payable {
        owner = msg.sender;
    }

    receive() external payable {}

    fallback() external payable {}

    function transfer(address payable _to, uint256 _amount) public {
        require(msg.sender == owner, "Only Contract owner can transfer balance");
        require(address(this).balance >= _amount, "Insufficient balance in contract");
        _to.transfer(_amount);
    }

    function getContractBalance() public view returns (uint256) {
        return address(this).balance;
    }
}
```
CODE EXPLANATION (key points):
- `owner` (public address) set to deployer (msg.sender) in constructor.
- `constructor() payable` -> can receive ETH at deployment (funds contract).
- `receive() external payable {}` -> auto-triggered when ETH sent w/ no function call/data.
- `fallback() external payable {}` -> triggered when unknown function called w/ data; also payable.
- `transfer()`: require #1 = only owner may call; require #2 = contract balance
  >= requested amount; then `_to.transfer(_amount)`.
- `getContractBalance()` = view fn, free to call, returns `address(this).balance`.
PROCEDURE:
1. Remix -> new file BalanceTransfer.sol -> paste code -> Compile (0.8.x compiler).
2. Deploy & Run Transactions tab -> ENVIRONMENT = any "Remix VM" (e.g. London).
3. Select Account 1 (becomes owner). Set VALUE field = 1, unit = ETHER (funds
   constructor). Select BalanceTransfer in CONTRACT dropdown -> click Deploy.
4. Read state: click `owner` -> shows Account 1 address. Click `getContractBalance`
   -> returns 1000000000000000000 (=1 ETH in Wei; 1 ETH = 10^18 Wei).
5. Send ETH after deployment: switch ACCOUNT to Account 2. Set VALUE = 500,
   unit = FINNEY (1 ETHER = 1000 FINNEY, so 0.5 ETH). In deployed contract's
   "Low level interactions", leave Calldata empty, click orange "Transact"
   (triggers receive()). getContractBalance -> now 1500000000000000000 (1.5 ETH).
6. Transfer (success case): copy Account 3 address. Switch back to Account 1
   (owner). In `transfer` fn: `_to` = Account 3 address, `_amount` = 200000000000000000
   (0.2 ETH in Wei). Click transfer. getContractBalance -> 1300000000000000000
   (1.3 ETH). Account 3 balance increases by 0.2 ETH.
7. Failure case 1 (not owner): switch to Account 2 (non-owner), call transfer
   with any amount -> reverts: "Only Contract owner can transfer balance".
8. Failure case 2 (insufficient funds): switch to Account 1 (owner); contract
   has 1.3 ETH; attempt `_amount`=2000000000000000000 (2 ETH) to Account 3 ->
   reverts: "Insufficient balance in contract".
FORMULA: 1 ETH = 10^18 Wei; 1 ETHER = 1000 FINNEY.
RESULT: BalanceTransfer contract compiled, deployed, funded, and tested (success
+ 2 failure/require cases) successfully.
VIVA: `payable` = allows fn/constructor to receive ETH. `require()` = condition
check; reverts tx + refunds gas-minus-used if false, with custom error message.
`msg.sender` = address calling current function. `receive()` vs `fallback()`:
receive() triggers on plain ETH transfer w/ empty calldata; fallback() triggers
on call to non-existent function or with data when no receive() matches.
